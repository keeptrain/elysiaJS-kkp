3. `invalidateProductListCache` / `invalidateProductDetailCache` di `cache.ts` juga jangan throw — gagal invalidasi lebih baik daripada 500 saat create/update
4. Verifikasi: `bunx tsc --noEmit`, `bunx biome check src/modules/products`, `bun test src/modules/products/_test` — semua hijau
5. (Opsional, manual) matikan redis lokal sementara lalu hit GET /products — harus tetap 200 dari DB


### Task 4 — Negative cache untuk detail 404 (perf)

1. Di `cache.ts`, tambahkan konstanta TTL pendek khusus miss (misal 60 detik) + helper untuk key/bangun nilai "not found" — pakai key yang sama dengan detail (`products:detail:<slug>`) supaya satu tempat invalidasi
2. Di `service.ts` `getProductBySlug`: saat hasil DB `null` (product tidak ada / tidak aktif / terhapus / org tidak ada), simpan penanda not-found ke redis dengan TTL pendek, dan return `null`
3. Saat baca cache: kalau yang terbaca penanda not-found → return `null` tanpa query DB
4. Pastikan `invalidateProductDetailCache` (dipanggil dari `updateProduct`) juga menghapus penanda not-found — supaya product yang tadinya 404 lalu dibuat/diaktifkan langsung bisa diakses
5. Tambah test: panggil `getProductBySlug` 2x untuk slug tidak ada — panggilan kedua tidak boleh query DB (bisa diverifikasi dengan mengubah/menghapus data di antaranya, atau cek key ada di redis); plus test update setelah 404 → data baru terbaca
6. Verifikasi: `bunx tsc --noEmit`, `bunx biome check src/modules/products`, `bun test src/modules/products/_test` — semua hijau
