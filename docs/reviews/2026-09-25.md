# Products Module Review — 2026-09-25

Urutan dari yang paling berisiko.

## Temuan

### 1. Redis down = semua GET 500 (paling penting)
`listProducts`/`getProductBySlug` fail-closed — `redis.get` throw → endpoint mati. Upstash free plan (kuota/rate-limit), jadi skenario ini realistis: kuota habis → list & detail 500 padahal DB sehat.
Fix: bungkus akses redis try/catch — miss → query DB, set → best-effort.

### 2. Slug duplikat bisa lolos (race)
`findProductBySlug` cuma pre-check, schema **gak ada unique constraint** di `(organizationId, slug)` — cuma index biasa. 2 create barengan → dua-duanya lolos cek → slug kembar, tanpa 409.
Fix: tambah `unique('uq_products_org_slug').on(organizationId, slug)` + catch PG `23505` → `PRODUCT_ALREADY_EXISTS`. Berlaku juga buat rename di `updateProduct`.

### 3. PATCH body kosong lolos
`UpdateProductBody` semua optional → `{}` valid → no-op update tapi tetap bump list version + DEL detail.
Fix: `t.Object({...}, { minProperties: 1 })` → 422.

### 4. 404 detail gak di-cache
Slug ngawur (crawler/bot) = DB hit terus.
Fix: negative cache TTL pendek (60 dtk) untuk `null`.

### 5. Shape cache ditulis 2x manual
`buildProductListFromCached`/`buildProductDetailFromCached` duplikat definisi row inline — udah sempat drift (`sku` ada di detail, gak ada di list).
Fix: 1 source of truth type (mis. export dari `model.ts`).

### 6. Minor
- `findProductBySlug` gak exclude soft-deleted → slug produk terhapus gak bisa dipakai ulang (mungkin memang mau begitu, tapi sadari)
- `list` gak return `sku` padahal detail ada — inkonsisten kalau frontend pakai keduanya
- Coverage kurang: rename clash → 409 di update, `ORGANIZATION_NOT_FOUND` di update — belum ada test-nya
